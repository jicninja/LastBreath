# Canonical Glossary

Project-wide canonical terms. Use these spellings exactly; do not invent synonyms.

## Resources

- **oxygen** — the main resource that depletes over time and ends the run at zero.
- **agitation** — the player's stress meter (0–100) that modulates oxygen drain.

## Threat

- **presence** — the unseen entity. Communicated only through environmental events; never visually confirmed.

## Spaces

- **interior** — the lit station interior; safer.
- **exterior** — the space-side walkway; higher drain, lower visibility.
- **airlock** — the transition between interior and exterior. Holds the airlock **save-point flag** that triggers the autosave (see ADR-0005).
- **corridor** — connective interior space (e.g., Corridor C-7).
- **layout** — a named sub-section of a scene. Identified by a `LAYOUT-*` ID in `docs/registry/architecture.yaml`. The corridor is one layout; the maintenance room is another. A scene is a container of one or more layouts. See ADR-0007.
- **scene spec** — the `*.layout.yaml` snapshot of a scene's composition, generated by `LevelSpec.DumpSpec` at the end of every level-design session. The reviewer-facing artifact for level-design changes (the `.unity` file is the executable artifact and is not the review surface). See ADR-0007 and `docs/process/level-design.md`.
- **session snapshot** — the commit bundle a level-design session ships: the updated `.unity`, the regenerated `scene spec`, two viewport screenshots, and a `session-NNNN.md` log. The session log template lives in `docs/process/level-design.md` `§6`.

## Art pipeline

- **art asset** — a 3D model produced by `asset-designer` via `blender-mcp`, identified by an `ART-*` ID in `docs/registry/architecture.yaml`. Lives first under `art/<asset>/`, then under `src/Assets/_Project/Art/<Category>/<AssetName>/` once imported. See ADR-0008.
- **asset manifest** — the `manifest.yaml` sidecar that accompanies every art asset. Carries provenance, licence, exports, screenshots, approval state, `imported_hash`. The reviewer's audit surface for asset-design changes; the `.glb` is the executable artifact. Schema in `docs/process/asset-design.md` `§5`.
- **staging area** — the folder `art/<asset>/` where new and in-flight assets live before approval. Outside `src/Assets/` so Unity does not auto-import them. The only place where a `manifest.yaml` lives.
- **approval gate** — the human-in-the-loop step that flips `manifest.approved` from `pending` to `true`. Only the user crosses this gate, via `/art-approval-queue`. Agents propose; the human decides. See ADR-0008 `§Approval gate`.
- **provenance** — the `manifest.provenance` block. Source-specific fields (`polyhaven_id`, `recipe_path`, `hand_authored_by`) that document where an asset came from. The reviewer fails the commit if it is missing.
- **import gate** — the `[MenuItem("LastBreath/Art/Import Approved Assets")]` Editor utility, the only path that moves a file from `art/<asset>/` into `src/Assets/_Project/Art/`. Wave B (`src/Assets/_Editor/Art/ApprovedAssetImporter.cs`).
- **glTF** / **`.glb`** — glTF 2.0 binary format. The canonical export format per ADR-0008. Covers PBR materials, lights (`KHR_lights_punctual` extension), and skinned rigs in a single file.
- **sync verifier** — the cross-tool parity check between `art/` and `src/Assets/_Project/Art/`. Two layers: Layer A (`scripts/check-art-sync.py`, hash + cross-reference, no Unity needed) and Layer B (`[MenuItem("LastBreath/Art/Verify Sync")]`, importer settings, Wave B). Run via `/verify-art-sync`. See ADR-0008 `§Sync verification`.
- **asset-designer** — the agent role that authors `art/**` and drives `blender-mcp` with the full author scope. Does not touch `.unity`, layouts, or `src/Assets/_Project/Art/`.

## Player tools and surfaces

- **flashlight** — the helmet light. The only light source the player controls.
- **panel** — a wall-mounted interactable that gates progress.

## Events and registry vocabulary

- **event** — a typed signal published by one system, consumed by zero or more subscribers. Identified by an `EVT-*` ID in `docs/registry/architecture.yaml`.
- **publisher** — the single system allowed to emit a given event. Each `EVT-*` has exactly one publisher.
- **subscriber** — any system that listens to a given event. An event may have many subscribers.
- **payload** — the typed data carried with an event. Documented in `architecture.yaml` and in the publisher's SDD section.
- **channel** — historically: a `ScriptableObject` event bus typed by payload, used for cross-scene fire-and-forget signalling. **Forbidden in new gameplay code** per ADR-0004 (rule `GAMEPLAY-CODE-FLAG-NO-SO-EVENT-CHANNEL`). The term remains documented here so older references resolve; the canonical pattern is now C# events on the publishing system, with `FlagSystem` as the custodian for persistent boolean state.
- **registry drift** — code introduces a class, event, or system that has no entry in `architecture.yaml`. The `code-reviewer` flags this under `REGISTRY-DRIFT-*`.

## Progression and save

- **flag** — a persistent boolean unit of world state, owned by `SYS-FLAGS` and identified by reference to a `FlagDefinition` (not by string outside debug APIs).
- **flag definition** — the `ScriptableObject` asset (`FlagDefinition`) that declares a flag's stable identity (`flagId`), display name, default value, and whether it is a save point.
- **flag graph** — the directed graph of flag transitions implied by interactables, cues, and gates. Many-to-many: one action can flip several flags; one flag can be required by several gates. Canonical term for what informal prose may call an "unlock graph".
- **gate** — a designer-wire `MonoBehaviour` (e.g., `FlagGate`) that reads one or more flags and exposes `UnityEvent` slots for designer-side reactions inside a single prefab. `UnityEvent` is allowed only on gates and on `FlagSetter`; never on systems.
- **narrative cue** — a one-shot piece of in-world communication (audio, text, optional flag-setting side effects) emitted by `SYS-NARRATIVE` when a `NarrativeCueDefinition`'s required flags become true.
- **save point** — a flag whose `FlagDefinition.isSavePoint` is `true`. Flipping it to `true` triggers `SaveSystem` to write the autosave.
- **persistence id** — a stable, scene-unique string assigned in the inspector to an `IPersistentInteractable` so its state can survive save and restore.
- **loading state** — the `GameState.Loading` value of `GameManager`. While active, no system publishes events; `SaveSystem` orchestrates restore and exits to `Playing` by publishing `EVT-save-restored` exactly once.
- **DTO** — a `[Serializable]` plain class (no Unity types beyond primitives, strings, lists, and `Vector3`-like primitives) used to transfer state between runtime systems and the on-disk save format. One DTO per saveable system; aggregated by `SaveData`.
- **saveable** — a system or component that implements `ISaveable<TDto>` and is referenced from `SaveSystem`. Saveables participate in the snapshot in any order; restore order is non-critical because of the `Loading` state gate.

## Ship AI and dialogue

- **ship AI** — the in-fiction operations AI of the station. Working name `MOTHER`. A character distinct from the **presence**: the ship AI speaks, the presence does not. Owned by `SYS-DIALOGUE`.
- **terminal** — a wall-mounted PC console the player can interact with. Diegetic chat surface for the ship AI. Peer of **panel**, not a subtype. Owned by `SYS-TERMINAL`.
- **inbox** — the per-terminal queue of one-way messages the ship AI has routed to a specific terminal via flag transitions. Reading the inbox costs no LLM call.
- **live channel** — the synchronous two-way request-response channel: the player types free-text, the ship AI replies. Each exchange consumes one LLM call against the **transport**.
- **mandate** — internal AI axis [0..1] measuring divergence between the player's current action and the AI's primary directive (preserve the ship). Higher = AI more likely to refuse or selectively omit.
- **integrity** — internal AI axis [0..1] measuring the AI's own functional state. Starts at 1.0 and monotonically drifts down. Lower = AI more likely to contradict itself or claim sensors offline. The AI does not know it is degrading.
- **budget** — internal AI axis [0..1] measuring spare resource (oxygen, power, access) the AI has to allocate. Lower = AI more likely to deny requests as accounting decisions.
- **mandate divergence**, **system integrity**, **budget pressure** — long forms of the three internal axes, used in design prose when the bare noun is ambiguous.
- **axis ambiguity** — the player-facing property that any reply may be driven by mandate, integrity, budget, or any mix, and the player cannot inspect which. This *is* the mechanic.
- **structured response** — the JSON shape the LLM is asked to return: `{ speech, mandateDelta, tags }`. The speech field is the only part the player sees; tags drive system reactions.
- **transport** — the seam between `SYS-DIALOGUE` and the LLM, exposed as `IDialogueTransport`. Default implementation is `OllamaHttpTransport`. Per ADR-0006.
- **mock transport** — `MockTransport`, the EditMode/offline implementation of `IDialogueTransport` that returns canned `TransportResponse`s. Never used in builds.
- **endpoint config** — the resolution chain for the LLM endpoint URL: env var `LASTBREATH_LLM_ENDPOINT` > `CFG-LLM-TRANSPORT.defaultEndpoint` > hardcoded `http://localhost:11434` fallback. Never an API key.
- **availability state** — the three-valued status of the ship AI for a given turn, computed before the transport is touched: `Online` (request/response normally), `Garbled` (canned reply, integrity ticks down), `Silent` (no reply, no integrity change). Owned by `SYS-DIALOGUE`. Per `SPEC-2026-05-12-ship-ai-context-and-runtime`.
- **availability rule** — a `MotherAvailabilityRule` ScriptableObject (`CFG-AVAILABILITY-RULE`) that maps a `(zone, requiredFlags, forbiddenFlags)` predicate to one **availability state**, with an integer priority for ordering. Identity-only SO per ADR-0004; designer-authored, never mutated at runtime.
- **garbled reply** — a canned, non-LLM reply chosen from `DialogueAIConfig.garbledReplies[]` when `availability state` is `Garbled`. Tagged `nonsequitur` + `false-claim`; ticks `integrity` down. Distinct from a `structured response`, which is the LLM JSON.
- **silent turn** — a turn whose `availability state` is `Silent`: the player text is recorded in history with an empty AI speech and `tags=["silent"]`, but no transport call is made and `integrity` is unchanged. Surfaced in the chat UI as a "NO RESPONSE" indicator.
- **focus label** — a designer-set string returned by `IFocusLabel.FocusLabel`, declared on interactables that the ship AI is allowed to refer to by name (e.g., `"airlock"`, `"breathing-station"`, `"panel C-7"`). The most recent non-null label seen during the run is exposed to the prompt as `lastSignificantInteraction`. `IInteractable` itself does not carry this — opt-in via the separate `IFocusLabel` interface.

## Camera, controls, and rendering

- **billboard (Y-axis)** — visual root of the player character that rotates only around world Y so its 2D sprite faces the camera horizontally. Camera pitch and roll do not propagate. Implemented in `LateUpdate` by `PlayerBillboard`. See ADR-0010.
- **side-rig** — the gameplay camera setup. A Cinemachine 3 `CinemachineCamera` (perspective, FOV ~35°) plus a `CinemachinePositionComposer` that follows the player on X and Z with light damping; Y is fixed. No look-ahead. Owned by `SYS-CAMERA`. See ADR-0010.
- **depth of field** / **DOF** — URP `Volume` post-process override that blurs out-of-focus geometry. In *Last Breath*, DOF runs in **Bokeh** mode (real focal separation, not uniform Gaussian blur). `focusDistance` is driven at runtime by `CameraDofDriver` against the player's distance to the camera.
- **action map** — a named group of input actions inside a `PlayerControls.inputactions` asset. The PoC has exactly one: `Gameplay`. Disabling the action map is the suppression seam used by terminal-open / pause / loading.
- **action asset** — the committed `.inputactions` file at `src/Assets/_Project/Input/PlayerControls.inputactions`. Registered as `CFG-PLAYER-INPUT`. Authored via the Unity Editor's `.inputactions` editor; never hand-edited.

## Roles

The nine roles defined in `AGENTS.md` and `.claude/agents/`:

- **game-designer** — owns `docs/gdd/**` (mechanic prose, scene flow, pillars).
- **systems-designer** — owns `docs/sdd/**` and `docs/registry/**` (system contracts, IDs).
- **gameplay-programmer** — owns `src/**` and `docs/tdd/**` (C# code, class docs).
- **unity-specialist** — owns Unity config in `src/**` (asmdef, packages, project settings).
- **level-designer** — owns scene composition: `docs/levels/**`, `.unity` content under `src/Assets/Scenes/**`, level prefabs under `src/Assets/_Project/Prefabs/Level/**`, level configs under `src/Assets/_Project/Config/Levels/**`. Drives `unity-mcp`; reads `blender-mcp` (read-only subset) for cross-tool verification. Imports approved art via `[MenuItem("LastBreath/Art/Import Approved Assets")]`. Does not touch gameplay code or engine config. See ADR-0007 and ADR-0008.
- **asset-designer** — owns the Blender-side art pipeline: `art/**` (staging) and `blender-mcp` author scope. Produces `.glb` + manifest + screenshots; never touches `.unity`, layouts, or `src/Assets/_Project/Art/`. The user (human) is the only approver. See ADR-0008.
- **qa-tester** — owns `tests/**` and test plans in `docs/plans/**`.
- **narrative-director** — owns narrative sections in `docs/gdd/**` (audio logs, panels, HUD copy).
- **code-reviewer** — read-only auditor; owns nothing. Dispatched at the end of every code, level, or asset change.

## Anti-glossary (do not use)

- "monster", "creature", "entity" — say `presence`.
- "stress", "fear meter", "panic" — say `agitation`.
- "air", "lungs" — say `oxygen`.
- "outside", "vacuum", "EVA" — say `exterior`.
- "message", "signal", "notification" (in code/architecture context) — say `event`.
- "listener", "handler" (in architecture context) — say `subscriber`.
- "unlock graph", "progression graph", "quest graph" — say `flag graph`.
- "checkpoint" (in save/restore context) — say `save point`. The word "checkpoint" survives only in legacy doc anchors; new prose uses `save point`.
- "boolean state", "world flag", "story flag" — say `flag`.
- "cue channel", "event channel", "BoolVariable", "GameEvent" (as `ScriptableObject` types) — forbidden by ADR-0004; use `FlagSystem` / `NarrativeDirector` + C# events instead.
- "savefile struct", "state struct" — say `DTO` (one per saveable system) plus the `SaveData` root.
- "computer", "console", "screen" (in the chat-mechanic context) — say `terminal`.
- "chatbot", "assistant", "NPC" (when referring to the ship AI) — say `ship AI` in design prose; in code, the system name is `SYS-DIALOGUE`.
- "API key", "secret", "credential" (in the LLM context) — there is no key handling this round; say `endpoint config` and cite ADR-0006.
- "AI trust meter", "hostility score", "alignment bar" — forbidden as design surface. The three axes (mandate, integrity, budget) are *internal* and never rendered to the player. Use `axis ambiguity` to talk about the player-facing property.
- "dialogue tree", "branching dialogue" — the live channel is free-text + structured response. The PoC has no trees.
- "AI offline meter", "ship AI status bar" — the `availability state` is *internal*; the player infers it from the chat UI feedback (no entry vs garbled glitch text), never from a meter. Same opacity logic as the three axes.
- "garbled response", "silent response" — overload `structured response` (which is glossary-bound to the LLM JSON shape). Use `garbled reply` and `silent turn`.
- "Input.GetAxis", "Input.GetKey", "legacy input" — forbidden in `src/Assets/_Project/**` per ADR-0010 and `UNITY-PATTERN-INPUT-SYSTEM`. Use `InputActionReference` against `PlayerControls.inputactions`.
- "orthographic camera", "ortho cam" — rejected by ADR-0010 (DOF Bokeh requires perspective). Re-introducing requires an ADR amendment.
- "follow with look-ahead", "predictive camera" — rejected by ADR-0010 (contradicts GDD line 103 "no fighting the input"). Say `side-rig` and tune damping.
- "shader billboard", "billboard shader" — the project uses a C# `LateUpdate` Y-axis billboard; no shader-side billboard. Rejected by ADR-0010.
- "PlayerInput component" — the Unity `PlayerInput` MonoBehaviour with auto-wiring + UnityEvents. Forbidden in `src/Assets/_Project/**` per ADR-0010; consumers use `InputActionReference` directly.
