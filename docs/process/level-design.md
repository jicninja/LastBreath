# Level design — the session loop

Canonical workflow for authoring and modifying a Unity scene. Read end-to-end the first time. Then jump to the section you need.

The decision behind this flow lives in `docs/decisions/0007-level-design-authoring-flow.md` (ADR-0007). The MCP setup lives in `docs/process/unity-mcp.md`. The rules the reviewer enforces live in `.claude/rules/level-design.md`.

## 1. Roles and scope

- `level-designer` owns scene composition: `docs/levels/**`, `src/Assets/Scenes/**.unity` content, `src/Assets/_Project/Prefabs/Level/**`, `src/Assets/_Project/Config/Levels/**`.
- `game-designer` owns intent: GDD scene flow (`docs/gdd/last-breath-poc-gdd.md#first-playable-scene`), pillar alignment, pacing.
- `gameplay-programmer` owns the C# under `src/Assets/_Project/Scripts/**`. Level design never edits gameplay code.
- `unity-specialist` owns engine config (URP, Input System, .asmdef, project settings). Level design never edits those.

If a level-design session needs new gameplay behaviour (e.g., a new interactable type), the session stops. The level-designer opens a plan in `docs/plans/` and hands off to the gameplay-programmer; the plan returns to level design once the new behaviour exists.

## 2. ID convention

| Layer | Prefix | Example | Casing |
|-------|--------|---------|--------|
| Scene (GDD container) | `SCENE-` | `SCENE-CORREDOR-C7` | UPPERCASE, English |
| Layout (sub-section of a scene) | `LAYOUT-` | `LAYOUT-C7-MAINTENANCE` | UPPERCASE, English |

Rules:

- Every layout entry must exist in `architecture.yaml` with `status: active` before it is referenced from a `.layout.yaml`.
- `LAYOUT-*` IDs are flat. A future plan may introduce nested layouts; until then, prefer naming long sections with hyphens (`LAYOUT-C7-MAINTENANCE-ANNEX`) over hierarchy.
- ASCII only.

## 3. Folder and file layout

```
docs/
  levels/
    <scene-kebab>/
      README.md                          # frontmatter + intent narrative + open questions
      <scene-kebab>.layout.yaml          # generated by DumpSpec; the audit artifact
      img/
        session-NNNN-overview.png
        session-NNNN-fpv.png
      sessions/
        session-0001.md
        session-0002.md
```

```
src/Assets/
  Scenes/
    <SceneName>.unity                    # the executable artifact
  _Project/
    Prefabs/
      Level/
        <PrefabName>.prefab
    Config/
      Levels/
        <SceneName>Invariants.asset      # LevelInvariants ScriptableObject
```

Naming:

- Scene asset: PascalCase, no spaces (`CorridorC7.unity`).
- Layout YAML: same kebab-case as the scene's doc folder (`corredor-c7.layout.yaml`). The historical Spanish "corredor" is preserved because `SCENE-CORREDOR-C7` is an immutable ID.
- Prefabs under `Level/`: PascalCase, single responsibility (`BreathingStation.prefab`, `ZoneTriggerInterior.prefab`, `FlickeringLamp.prefab`).
- Session log: `session-NNNN.md`, four-digit zero-padded, monotonically increasing across the scene's lifetime.

## 4. The session loop

```
goal stated  →  MCP iterate (Claude + user, Unity open)  →  user validates
                                                              ↓
                                                       still iterating?
                                                              ↓
                                                       user happy
                                                              ↓
                                                end-of-session snapshot
                                                              ↓
                                                       commit bundle
                                                              ↓
                                                       review-level
```

Steps:

1. **State the goal.** The level-designer writes the session's goal in plain English at the top of the new `session-NNNN.md`. One sentence. ("Lay out the cabin start area with breathing station and a single ambient panel.")
2. **Iterate via MCP.** The level-designer drives `unity-mcp` to add, move, parent, configure, and remove nodes. The user is in Unity, watching, validating. Many micro-iterations are normal.
3. **Snapshot.** When the user is satisfied:
    1. Run `LastBreath > Level > Dump Spec` (or `LevelSpec.DumpSpec(scenePath)` via MCP). Writes `docs/levels/<scene>/<scene>.layout.yaml`.
    2. Run `LastBreath > Level > Validate`. Must return no errors. If it returns errors, fix them in MCP and re-dump.
    3. Capture two viewport screenshots: `img/session-NNNN-overview.png` (top-down or 3/4) and `img/session-NNNN-fpv.png` (first-person from `PlayerSpawn`). The MCP can save the viewport directly to those paths.
    4. Write `sessions/session-NNNN.md` from the template in §6. Three to ten bullets, not an essay.
4. **Idempotency check.** Run `LastBreath > Level > Apply Spec` on a scratch copy of the scene. Compare to the working scene. They must match (modulo non-load-bearing GUID noise — `LevelSpec.ApplySpec` documents the tolerated diff).
5. **Commit bundle.** Stage in a single commit: the `.unity`, any new `.prefab` / `.asset`, the `.layout.yaml`, both screenshots, the session log.
6. **Review.** Run `/review-level` (or `/review-level --strict` before merge). The reviewer reads the spec, the session log, and the screenshot filenames — never the raw `.unity` diff.

## 5. Spec format

`docs/levels/<scene>/<scene>.layout.yaml` is generated, not hand-written. The reference schema:

```yaml
scene: SCENE-CORREDOR-C7
spec_version: 1
generated_at: 2026-05-12T18:42:10Z
generator: LevelSpec.DumpSpec v1

layouts:
  - id: LAYOUT-C7-CABIN
    root_node: /Root/Cabin
    transform: { pos: [0, 0, 0], rot: [0, 0, 0], scale: [1, 1, 1] }
    children:
      - name: PlayerSpawn
        type: Marker
        transform: { pos: [0, 1, 0], rot: [0, 0, 0], scale: [1, 1, 1] }
      - name: BreathingStation
        type: Prefab
        prefab: src/Assets/_Project/Prefabs/Level/BreathingStation.prefab
        transform: { pos: [2.5, 0, 0], rot: [0, 180, 0], scale: [1, 1, 1] }
        overrides:
          flag_ref: CFG-FLAG/cabin_oxygen_station_used
      - name: ZoneTrigger_Interior
        type: EnvironmentZoneTrigger
        zone: Interior
        bounds: { center: [0, 1.25, 0], extents: [3, 1.5, 3] }

  - id: LAYOUT-C7-CORRIDOR
    root_node: /Root/Corridor
    transform: { ... }
    children: [ ... ]
```

Rules:

- The `generator` field encodes the dumper version. A spec from an older dumper is regenerated by the current dumper before use; never hand-merged.
- Component-level data is summarised: only the fields the level-designer can author through the editor are captured. Fields owned by the gameplay layer (private state, runtime-only) are excluded.
- Prefab references are by `src/Assets/_Project/Prefabs/Level/...` path. Renaming a prefab requires updating every spec that references it; the reviewer flags broken refs.
- `flag_ref`, `presence_event_ref`, `objective_ref` use the form `<CFG-PREFIX>/<asset-name>`. The reviewer resolves these against `architecture.yaml` and the matching `.asset` files.

## 6. Session log template

`docs/levels/<scene>/sessions/session-NNNN.md`:

```markdown
---
session: NNNN
scene: SCENE-<NAME>
date: YYYY-MM-DD
duration_minutes: <int>
participants: [level-designer, user]
---

## Goal
One sentence.

## What landed
- ...
- ...

## What got rejected
- ...

## Open questions
- ...

## Hand-offs
- (none) | <role>: <one sentence>
```

Rules:

- "What landed" lists changes the user accepted. Three to ten bullets.
- "What got rejected" is short but real — it documents the path not taken so future sessions do not relitigate.
- "Hand-offs" is the only async-communication channel between roles. If the session needed a new interactable type, the hand-off line says so; the gameplay-programmer reads it before opening the next plan.

## 7. Editor utility verbs

Implemented in `src/Assets/_Editor/Level/LevelSpec.cs` (Editor-only assembly, lands in the same plan that creates the Unity project). The MCP calls these through menu items so the assistant has high-level verbs:

- `LastBreath > Level > Dump Spec` — `LevelSpec.DumpSpec(scenePath) → yamlPath`.
- `LastBreath > Level > Apply Spec` — `LevelSpec.ApplySpec(yamlPath, targetScenePath)`.
- `LastBreath > Level > Validate` — `LevelSpec.ValidateScene(scenePath) → ValidationReport`.

The `LevelInvariants` ScriptableObject (one per scene, under `src/Assets/_Project/Config/Levels/`) declares what `ValidateScene` checks for that scene. Default invariants:

1. Every `EnvironmentZoneTrigger` is non-overlapping with peer zone triggers.
2. At least one trigger flips a `FlagDefinition` with `isSavePoint: true`.
3. Every interactable references a `FlagDefinition` registered in `CFG-FLAG`.
4. The objective node (`Objective_AntennaPanel`) is reachable from `PlayerSpawn` along the navigable surface.

A scene that needs extra invariants extends its `LevelInvariants` asset.

## 8. What the reviewer enforces

See `.claude/rules/level-design.md` for stable rule IDs. Cheat sheet:

- `LEVEL-DESIGN-NO-DIRECT-UNITY-EDIT-WITHOUT-SPEC` — every `.unity` change has a matching `.layout.yaml` change.
- `LEVEL-DESIGN-SPEC-IS-IDEMPOTENT` — `ApplySpec(DumpSpec(scene)) == scene` is asserted by an EditMode test.
- `LEVEL-DESIGN-LAYOUT-ID-REGISTERED` — `LAYOUT-*` IDs in the spec exist in `architecture.yaml`.
- `LEVEL-DESIGN-NO-LOOSE-MAGIC` — interactables/triggers reference registered configs, not string literals.
- `LEVEL-DESIGN-INVARIANTS-PASS` — `ValidateScene` returns no errors.
- `LEVEL-DESIGN-NO-GAMEPLAY-CODE` — the diff does not change `src/Assets/_Project/Scripts/**`.

## 9. What this process is NOT for

- Tuning balance numbers — that lives in tuning ScriptableObjects (`CFG-OXYGEN`, `CFG-AGITATION`) and is owned by `game-designer`.
- Writing new C# — that is `gameplay-programmer` work; the level-designer hands off via the session log.
- Engine config (URP volumes, Input System bindings, render pipeline assets) — that is `unity-specialist` work.
- Narrative copy (terminal text, panel inscriptions) — that is `narrative-director` work; the level-designer wires the references but does not write the strings.

## 10. Acceptance checklist for a level-design commit

The `code-reviewer` will look for every box below on a level-design diff.

- [ ] The diff touches `src/Assets/Scenes/**.unity` and `docs/levels/<scene>/<scene>.layout.yaml` together (or neither).
- [ ] `docs/levels/<scene>/sessions/session-NNNN.md` is added with the four sections (Goal, What landed, What got rejected, Open questions) filled.
- [ ] Two screenshots `img/session-NNNN-overview.png` and `img/session-NNNN-fpv.png` are committed.
- [ ] Every `LAYOUT-*` referenced in the spec exists in `architecture.yaml`.
- [ ] No new entries under `src/Assets/_Project/Scripts/**` (unless an explicit cross-role plan says so).
- [ ] `LevelSpec.ValidateScene(scene)` returns no errors (manually run, or asserted by an EditMode test).
- [ ] Canonical glossary in prose (`oxygen`, `agitation`, `presence`, `interior`, `exterior`, `airlock`, `corridor`, `flag`, `save point`).
